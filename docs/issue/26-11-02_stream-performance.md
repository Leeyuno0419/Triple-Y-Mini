# 실시간 스트림 저 FPS 개선

## 문제

YouTube 라이브 주소 모드에서 화면이 약 0.9 FPS로 갱신됐다. 초기에는 원본 해상도 얼굴 검출이 느렸고, 검출 입력을 줄인 뒤에도 프레임 갱신이 약 1 FPS에 머물렀다.

## 원인과 해결

- CPU에서 1280×720 프레임을 검출하는 데 약 2.5초가 걸렸다. 검출 입력의 긴 변을 최대 640px로 축소하고, 검출 좌표를 원본 크기로 환산해 원본 프레임에 모자이크를 적용하도록 변경했다.
- 추가 측정 결과, YouTube HLS 프레임은 세그먼트 단위로 몰려 들어왔다. 캡처 스레드가 프레임을 한꺼번에 읽으면서 최신 프레임만 남기는 방식 때문에 대부분의 프레임이 덮어써졌다. 캡처 프레임을 소스 FPS에 맞춰 일정한 간격으로 전달하도록 변경했다.

## 결과

- 검출 입력 축소 후 검출 시간: 약 2.5초 → 약 0.1초/프레임(워밍업 이후).
- 캡처 페이싱 적용 후, 같은 YouTube 라이브에서 연결 대기 이후 약 10 FPS를 측정했다.
- 출력 프레임은 원본 크기이며 모자이크도 원본 프레임에 적용한다.
- Streamlit 서버 헬스 체크: `ok`.
